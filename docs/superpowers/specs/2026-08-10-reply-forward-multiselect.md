# Настоящий ответ, пересылка с атрибуцией, мультивыбор, разделитель непрочитанных

Дата: 2026-08-10. Связка из четырёх пунктов гап-анализа «чего не хватает до Telegram».
Делаются вместе, потому что живут в одном экране, одном событии отправки и требуют
одной миграции.

## Что не так сейчас

**Ответ подделан.** `chat_room_screen.dart:1322-1328` вклеивает цитату в текст
сообщения: `↩ Имя: «первые 60 символов»\nтекст`. Поля `replyToId` нет нигде.
Следствия: нельзя прыгнуть к оригиналу; цитата не меняется при редактировании и
переживает удаление оригинала; поиск индексирует цитату как обычный текст; обрезка
до 60 символов необратима; в пуш уходит вместе с цитатой.

**Пересылка — копия.** `messenger_bloc.dart:1590-1597` просто отправляет `content`
в другой чат. Нет «Переслано от X», нет источника.

**Мультивыбора нет** совсем. **Разделителя непрочитанных нет** — при входе в чат с
сотней непрочитанных пользователь оказывается внизу.

## Модель данных

Одна миграция, четыре колонки в `Message`:

```prisma
replyToId              String?
replyTo                Message?  @relation("MessageReplies", fields: [replyToId], references: [id], onDelete: SetNull)
replies                Message[] @relation("MessageReplies")
forwardedFromUserId    String?
forwardedFromName      String?   // снимок имени на момент пересылки
forwardedFromMessageId String?
@@index([replyToId])
```

`onDelete: SetNull`, а не Cascade: жёсткое удаление оригинала не должно уносить
ответы. Мягкое удаление (`deletedAt`) оставляет строку, и цитата показывается как
«Сообщение удалено».

Имя отправителя оригинала пересылки хранится **снимком** (`forwardedFromName`):
пользователь может сменить имя или удалиться, а атрибуция должна остаться той, что
была видна в момент пересылки.

## Ответ (reply)

Сокетное событие `message` получает необязательный `replyToId`.

Проверки в `createMessage` (единственная точка входа всех путей записи):
- оригинал существует, `deletedAt: null`;
- **тот же `conversationId`**, иначе `BadRequestException` — иначе через ответ можно
  вытащить кусок чужой переписки в свою;
- тот же `topicId` (обе стороны null-safe) — ответ через топик рендерится мусором;
- невалидный `replyToId` — ошибка, а не молчаливое обнуление: клиент должен узнать.

## Пересылка (forward)

**Новый REST-эндпоинт**, а не параметр сокета:

```
POST /messenger/conversations/:id/forward   { messageIds: string[] }
```

Причины:
1. Сервер сам копирует `content` и файловые поля из оригинала — клиент не может
   подделать атрибуцию, приписав чужое имя произвольному тексту.
2. Сервер проверяет, что пересылающий **участник исходной беседы**. Без этого любой
   аутентифицированный пользователь пересылал бы себе любое сообщение по id.
3. Массив id сразу закрывает пересылку из мультивыбора — отдельного API не нужно.

Пересылка пересылки не наслаивается: если у оригинала уже есть `forwardedFromUserId`,
он копируется как есть (Telegram ведёт себя так же — цепочка не растёт).

Лимит на пачку — 50 сообщений за запрос.

## Форма ответа

К каждому сообщению добавляются:

```jsonc
"replyToId": "…",
"replyTo": {            // null, если ответа нет
  "id": "…", "senderId": "…", "senderName": "…",
  "content": "…",       // обрезано до 200 символов
  "fileType": "image", "fileName": "…",
  "isDeleted": false    // true → клиент рисует «Сообщение удалено»
},
"forwardedFrom": {      // null, если не пересылка
  "userId": "…", "name": "…", "messageId": "…"
}
```

⚠️ `sync` собирает выдачу **сырым SQL** со списком колонок
(`messenger.service.ts:719+`). Новые колонки надо добавить и туда, иначе на пути
кросс-девайсной синхронизации ответы поедут пустыми, а через `getMessages` будут
приходить — расхождение, которое ловится только вручную.

## Мультивыбор

Клиентский режим: долгий тап включает выделение, тап добавляет/убирает. Действия над
пачкой: удалить, переслать (эндпоинт выше), скопировать. Потолок выделения — 50,
совпадает с лимитом пересылки.

## Разделитель непрочитанных

Полностью клиентский: данные уже есть в `ConversationParticipant.lastReadMessageId`
и отдаются через `GET /messenger/conversations/:id/read-state`. При открытии чата —
линия «N новых сообщений» перед первым непрочитанным и стартовая позиция на ней, а
не в самом низу. Линия держится, пока чат открыт, и не переезжает от приходящих
сообщений.

## Совместимость

Все поля необязательные, старые клиенты их игнорируют. Старые ответы-цитаты в тексте
остаются как есть — миграции текста в `replyToId` не делаем: разобрать `↩ Имя: «…»`
обратно нельзя надёжно, а испортить текст можно.

Новый клиент, увидев старое сообщение без `replyToId`, показывает его как обычный
текст — то есть ровно так, как оно выглядит сегодня.

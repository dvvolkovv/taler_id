# Веб-комната: раскладка под поворот телефона

Дата: 2026-08-28
Файл: `public/room.html`

## Задача

Гостевая веб-комната (`https://<хост>/room/<id>`) на телефоне не реагирует на поворот
экрана. В горизонтальной ориентации шапка и нижняя панель кнопок съедают почти всю
высоту, плитки участников 16:9 в неё не помещаются и сетка уезжает в прокрутку.
Экран до входа обрезается: иконка 88px с отступами не влезает в ~350px высоты.

Нужно: при повороте в горизонт раскладка перестраивается, при возврате в портрет —
возвращается к текущей.

## Что есть сейчас

- Единственный брейкпоинт — `@media (max-width: 640px)`, он делает чат полноэкранным.
- `.call-room` — вертикальный flex: шапка → баннеры записи/транскрипции →
  `.call-body` (видео + панель чата) → `.controls`.
- `updateTileLayout()` раздаёт плиткам ширину лесенкой от числа участников
  (`90% / 45% / 30% / 22% / 18%`), размер контейнера не учитывается.
- Слушателей `resize` / `orientationchange` нет вообще — после поворота ничего
  не пересчитывается.
- `showStep()` управляет видимостью экрана звонка через инлайновый `style.display`.

## Решение

### Точка переключения

```css
@media (orientation: landscape) and (max-height: 550px) and (pointer: coarse)
```

Только телефоны. Планшеты и десктопные браузеры с низким окном не задеты. Состояния
нет — возврат в портрет происходит сам собой.

### Каркас комнаты

В горизонте `.call-room` переключается с flex-колонки на grid:

```
grid-template-columns: 1fr auto;          /* контент | панель кнопок */
grid-template-rows: auto auto auto 1fr;   /* шапка | баннер записи | баннер транскрипции | тело */
```

Шапка и баннеры остаются в первой колонке, `.controls` занимает вторую во всю высоту.
DOM не меняется. Баннеры по умолчанию `display:none`, их строки схлопываются в ноль.

Инлайновый `display` в `showStep()` перекрыл бы медиазапрос, поэтому видимость
экрана звонка переезжает на класс `.in-call`: базовое `.call-room { display:none }`,
`.call-room.in-call { display:flex }`, в горизонте — `display:grid`.

### Панель кнопок

Одиннадцать кнопок в один столбик не влезают в ~330px (52px × 11 = 570px). В горизонте
панель — сетка в две колонки: кнопки 40px, текстовые подписи скрыты, стрелки выбора
устройства `▾` остаются, всплывающие списки открываются слева от панели, а не сверху.
Шесть рядов ≈ 280px, помещается. Ширина панели ~100px.

### Плитки участников

Лесенка процентов заменяется подбором по месту: для числа колонок от 1 до N считается
ширина плитки и её высота при 16:9, варианты, не влезающие в высоту сетки, отбрасываются,
берётся самый крупный. Результат ограничивается сверху прежними максимумами
(600/500/400/320/260px) — на десктопе пропорции не меняются, ужимание срабатывает
только когда места действительно мало. Заодно чинится портрет с шестью участниками.

Пересчёт вешается на `ResizeObserver` над `.video-grid`: он покрывает и поворот, и
открытие чата, и полноэкранный режим. Плюс `orientationchange` с задержкой 300мс —
iOS Safari отдаёт размеры не сразу.

### Мелочи горизонта

- Шапка: отступы 6px, иконка 28px, у кнопки «Ссылка» остаётся только значок.
- Лента мини-плиток в режиме докладчика: 84px → 56px.
- Панель чата: 340px → 280px.
- Отступы под вырез экрана (`env(safe-area-inset-left/right)`) в шапке и панели кнопок.

### Экран до входа

Иконка 88 → 56px, отступы вдвое меньше, `body` выравнивается по верху с прокруткой —
кнопка «Войти в комнату» перестаёт обрезаться.

## Проверка

Файл отдаётся с диска (`res.sendFile` в `src/app.controller.ts`), сборка не нужна —
достаточно `git pull` на ноде.

- Chrome DevTools device mode: iPhone 14, поворот в обе стороны, 1/2/4/7 участников.
- Живьём на iPhone Safari и Android Chrome: вход в комнату, поворот туда-обратно,
  открытие чата, режим докладчика, выбор микрофона.
- Регресс десктопа: раскладка при 1..7 участниках не должна отличаться от текущей.

Раскатка: DEV → TEST → PROD.

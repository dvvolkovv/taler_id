# Чат в комнате: мобилка, десктоп и серверная ручка

Дата: 2026-09-03
Репозитории: `taler_id` (бэкенд, `public/room.html`), `taler_id_mobile` (мобилка + десктоп)

## Задача

Участники звонка должны переписываться в комнате независимо от того, с чего
зашли. Сейчас это умеют только браузеры.

## Что есть сейчас

Чат в веб-комнате реализован целиком и работает между веб-клиентами:

- отправка — `sendChatMessage()` в `public/room.html`, пакет уходит в data-канал
  LiveKit с `{ type: 'chat_message', text, name, ts }`, `reliable: true`;
- приём — ветка `msg.type === 'chat_message'` в обработчике `RoomEvent.DataReceived`;
- панель, счётчик непрочитанных, автоскролл.

Чего нет:

- **Мобилка и десктоп.** `_handleDataReceived` в
  `lib/features/voice/presentation/screens/voice_call_screen.dart` разбирает
  согласие на запись, статус транскрипции и прочее, но ветки `chat_message`
  в `switch` нет. Сообщение из браузера приходит и молча отбрасывается,
  отправить с приложения нечем.
- **Серверный доступ.** Обмен идёт мимо бэкенда, ручки для записи в чат нет.

## Решение

### 1. Протокол

Не меняется. Тот же `chat_message` в data-канале LiveKit, `reliable`.
Новые участники обмена (приложение, сервер) шлют ровно тот же JSON.

Одна правка в вебе: `sendChatMessage()` публикует пакет напрямую через
`publishData`, минуя `broadcastData()`, — а `msgId` для дедупликации проставляет
именно `broadcastData`. Пока отправитель один, это сходит с рук; с появлением
приложения и сервера повторы станут заметны. Отправка чата переводится на
`broadcastData`. Дедупликация на приёме уже есть с обеих сторон
(`_processedMsgIds` в вебе, `_processedMessageIds` в приложении).

### 2. Приложение — мобилка и десктоп

Экран звонка общий для всех платформ (`app_router.dart` импортирует единственный
`voice_call_screen.dart`), поэтому одна правка закрывает и телефоны, и
macOS/Windows/Linux. Но в файле 5949 строк, поэтому чат в него не сваливается:

- `voice/presentation/widgets/room_chat_panel.dart` — панель: лента сообщений,
  поле ввода, кнопка отправки;
- контроллер состояния чата: список сообщений, счётчик непрочитанных, флаг
  открытости панели. Отдельный класс, тестируемый без виджетов. Дедупликация
  по `msgId` в нём не нужна — она уже сделана централизованно в начале
  `_handleDataReceived`, до разбора типа пакета;
- в `voice_call_screen.dart` — только `case 'chat_message'` в
  `_handleDataReceived`, кнопка с бейджем непрочитанных в панели управления
  и подключение виджета.

Раскладка: на узком экране панель поверх звонка, на широком окне десктопа —
боковой панелью, как в вебе.

### 3. Ручка на бэкенде

`POST /voice/rooms/:roomName/chat`, тело `{ text }`.

Внутри — `RoomServiceClient.sendData(roomName, payload, DataPacket_Kind.RELIABLE)`
с тем же JSON, что шлют клиенты. `RoomServiceClient` бэкенд уже держит в
`voice.service.ts`.

Авторизация — существующий `RoomAccessGuard`: принимает либо LiveKit-токен,
выданный ровно на эту комнату, либо токен Taler ID участника звонка или владельца
персональной комнаты. Требует параметр `:roomName`, что совпадает с формой ручки.
Тем же guard'ом закрыто управление записью, так что новых правил про права
не появляется.

Валидация: обрезка пробелов, отказ на пустом тексте, потолок 500 символов —
как в веб-поле ввода.

Комнат две группы — европейская и российская, у каждой свой SFU и свой
`RoomServiceClient`. Выбор уже написан: приватный `sfuFor(roomName)` отдаёт
клиент по префиксу имени (`call-ru-…` → Selectel, остальное → EU/DO). Новый
метод берёт клиент оттуда же, а не обращается к `this.rooms` напрямую, иначе
для CIS-участников сообщение ушло бы в другую комнату.

### 4. Ассистент

По правилу Assistant-first: tool `send_room_chat` в
`lib/features/assistant/tools/assistant_tools_schema.dart`, исполнение в
`assistant_tools_executor.dart` — вызов новой ручки. Вне звонка tool отвечает
внятной ошибкой, а не шлёт в никуда.

### 5. Вне объёма

История сообщений (решено — чат эфемерный, как сейчас в вебе: вошедший позже
не видит написанного до него, после звонка переписка исчезает), вложения,
личные сообщения одному участнику.

## Проверка

- Юнит-тесты контроллера чата в приложении: разбор пакета, счётчик непрочитанных,
  дедупликация по `msgId`.
- Спека на новый метод сервиса и на доступ к ручке — рядом с существующей
  `src/voice/guards/room-access.guard.spec.ts`.
- E2E в `taler_id_tests`: пост через ручку и проверка, что подключённый к комнате
  клиент получил пакет. Набор `test:recording` уже подключается к комнатам
  по-настоящему, инфраструктура для этого есть.
- Руками: веб, телефон и десктоп в одной комнате, сообщения в обе стороны.

## Раскатка

Бэкенд катится отдельно (DEV → TEST → PROD). Чат в приложении уедет со следующей
сборкой; версию в `/app/version` и `APP_RELEASES` объявлять только после того,
как артефакты лягут на место — правило из CLAUDE.md.
